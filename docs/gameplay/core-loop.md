# 游戏核心主循环（固定规则）

## 规则地位

本文件是游戏核心流程的唯一规则来源，适用于客户端、房间服务器、大厅业务、内容格式和共创内容。

核心主循环不属于共创扩展范围。未经用户明确要求变更核心规则，AI、内容创作者和普通功能任务不得修改、绕过、删除或重排本文件定义的阶段。新玩法只能接入固定流程允许的内容位置。

本文件定义产品行为，不限定所有阶段必须使用同一技术房间或进程实现。

首版已落地的实例参数、代码状态和未补齐的流程行为见 [当前实现与开发交接](../current-state.md)。实例参数不自动成为平台通用政策。

## 核心概念

林地围猎后续已确认持续波次与灵魂复活的实例设计，和本文多轮小秘境流程存在差异，见 [后续已确认设计与文档差异](../implementation/forest-survival.md#后续已确认设计与文档差异)。波次不等同于小秘境轮次，该实例设计不自动推广为所有秘境的通用流程。

| 概念 | 含义 |
| --- | --- |
| 游戏大厅 | 局外空间，提供秘境列表、房间入口及角色强化、经营和物资购买等功能 |
| 房间 | 玩家选择某个秘境后创建的组队与本次秘境会话，承载整次秘境流程，不按每轮重新创建玩家会话 |
| 完整秘境 | 一次完整冒险，由秘境大厅及按轮次进行的多个小秘境构成 |
| 秘境大厅 | 本次完整秘境内部的休息、等待与轮间成长空间，不等于游戏大厅，也不等于开局前的等待房间 |
| 小秘境 | 当前轮执行具体玩法的空间，各轮内容可以不同 |
| 小秘境结算 | 每轮玩法完成后进行的单轮奖励结算 |
| 秘境最终结算 | 完成全部小秘境后，对本次完整秘境进行的个人奖励结算 |

## 账号与入场流程

1. 用户创建账号。
2. 用户选择初始角色，完成账号初始化。
3. 用户进入游戏大厅。
4. 游戏大厅提供秘境列表。
5. 用户选择需要的秘境并创建房间，其他用户加入对应房间。
6. 等待其他玩家加入后，开启本次完整秘境。
7. 本次玩家共同进入秘境大厅，开始首次休息与等待倒计时。

初始角色选择属于账号初始化，不要求后续每次登录或进入秘境都重新选择初始角色。

## 秘境内的固定循环

1. 玩家在秘境大厅休息等待；轮间返回时在此进行成长。
2. 等待时间结束，全体玩家统一传送到当前轮小秘境；首次进入的是第一个小秘境。
3. 玩家进行并完成当前轮的小秘境玩法。
4. 进行当前轮的小秘境奖励结算。
5. 如果还有下一轮，玩家返回秘境大厅进行成长，并进入下一次休息等待倒计时。
6. 倒计时结束后，全体玩家进入下一轮小秘境，重复上述流程。
7. 全部小秘境完成后，进行整个秘境的最终奖励结算。
8. 最终结算后，向每位玩家弹出本局结算界面，显示该玩家当前局的收益内容；玩家主动点击关闭后返回游戏大厅。

每轮小秘境都要结算，最后一轮不能以最终结算替代单轮结算。完成单轮结算和最终结算后返回游戏大厅。

```text
创建账号 → 选择初始角色 → 游戏大厅
                              ↓
                   选择秘境 → 创建/加入房间
                              ↓
                        等待玩家 → 开启
                              ↓
                     秘境大厅休息等待
                              ↓ 倒计时结束
                       当前轮小秘境玩法
                              ↓
                         小秘境结算
                              ↓
                       是否还有下一轮？
                       ├─ 有 → 秘境大厅成长 → 休息等待 → 下一轮
                       └─ 无 → 秘境最终结算 → 弹出个人结算界面 → 玩家关闭后返回游戏大厅
```

## 失败终止分支

全队倒地时，终止剩余小秘境，执行当前轮失败结算 → 每位玩家独立最终结算 → 弹出个人结算界面 → 玩家主动关闭后返回游戏大厅。失败惩罚遵守 [死亡与秘境失败惩罚](failure-penalties.md)。上述完整轮次循环描述正常通关路径，失败分支不得绕过结算或返回大厅。

## 最终结算界面与返回

- 最终结算完成后，弹出该玩家的本局结算界面，展示当前局的收益内容；失败损失和经验扣除应与收益明确区分。
- 玩家主动点击关闭结算界面后，该玩家返回游戏大厅。
- 每位玩家独立关闭、独立返回，不等待其他玩家确认，不强制全员同时返回。
- 不设置自动返回倒计时，不通过全员已阅或房主操作替代个人主动关闭。
- 关闭界面是离开结算展示的操作，不是发奖、处罚或再次结算的触发条件；个人结果由服务器保存。

## 两层结算

- 小秘境结算记录当前轮的成果与奖励；不能把它当成整次秘境结束。
- 积分获取规则由各秘境设计，平台不统一限制积分来源、得分行为或分值；不同秘境无需采用相同的获取规则。
- 最终结算根据本次秘境成果进行个人奖励结算，奖励包含流通货币及角色经营相关奖励，用于游戏大厅的角色强化、经营和物资购买。
- 两层结算必须在数据与流程上区分，不能共用一个无法区分轮次的奖励记录。
- 两层结算均按每个玩家独立进行，保存各自的成果、奖励及结算状态；记录和防重复要求见 [结算规范](../../apps/api-server/rules/settlement.md)。个人独立结算不改变统一传送与阶段推进。
- 最终结算是玩家返回游戏大厅前的固定环节，具体发放与重试由结算规范约束；结算后的返回由各玩家主动关闭个人界面触发。

## 固定流程与可创作内容

共创内容可以提供小秘境地图、怪物、技能、事件、目标及符合接口的玩法和完成条件。小秘境完成条件只控制本轮结束，不代表可以结束整次秘境。

完整秘境可以在平台允许的配置范围内编排小秘境内容。内容作者不能自行增加跳过流程的入口。

以下行为禁止作为普通内容扩展：

- 跳过账号初始化或以内容包替换账号、大厅系统。
- 开启秘境后直接绕过首次秘境大厅等待。
- 在非最后一轮结算后绕过返回秘境大厅、成长与倒计时。
- 让某个玩家自行切换到下一轮，破坏正常流程中的统一传送。
- 每完成一轮便结束整次会话，要求玩家重新创建或加入房间。
- 跳过小秘境结算、最终结算或最终返回游戏大厅。
- 由小秘境脚本自行发放永久资产，或修改核心阶段转换规则。
