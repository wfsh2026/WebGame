# 核心战斗规则：心法供能与能力连接

## 规则地位与适用范围

本文件统一定义心法、角色资源、武器、技能和辅助之间的核心关系，是这些机制的唯一规则来源。内容共创只能在该结构内配置和组合，不能自行替换资源链路、共享关系和独立计时规则。修改核心关系需要用户明确要求。

本规范与 [核心主循环](core-loop.md) 配合使用，不改变秘境大厅、各轮小秘境及两层结算流程。当前有独立的本地构筑原型和真实联机首版；联机版已在服务端实现共享供能、独立计时和正式命中。首版参数见 [当前实现](../implementation/forest-survival.md)，连续表现职责见 [客户端同步规则](client-presentation.md)，不能混用原型默认值。

## 概念与术语

| 名称 | 定义 |
| --- | --- |
| 魔力属性 | 增加角色魔法攻击力的基础属性，不是可消耗资源 |
| 角色魔法值 | 心法恢复时扣除的角色当前资源，具有最大值 |
| 灵力属性 | 增加角色最大魔法值和魔法防御的基础属性，不是心法当前储量 |
| 心法灵力池 | 心法独立管理的可消耗能量池，有自己的容量上限和当前灵力量 |
| 实际能力 | 连接在心法上的武器攻击或技能效果 |
| 辅助格 | 实际能力提供的装配位置，用于放置辅助技能或辅助物品 |

不得把心法灵力池与角色魔法值合并，也不得把恢复消耗错误地扣在魔力或灵力基础属性上。

## 固定连接结构

角色、怪物及能力表现遵守 [实体显示与控制](entity-controls.md)。

涉及物品等级、槽位解锁和局内强化时，同时读取 [构筑成长规范](build-growth.md)。升级后的连接仍遵守下述共享供能、辅助归属与独立计时规则。

```text
角色当前魔法值
    ↓ 心法每次恢复时消耗
心法灵力池（容量上限、恢复间隔、单次恢复量、恢复成本）
    ├─ 实际能力槽 → 武器 → 该武器的辅助格
    └─ 实际能力槽 → 技能 → 该技能的辅助格
```

- 心法决定能连接几个实际能力，能力不能超过它提供的槽位数量。
- 每个武器或技能决定自己提供几个辅助格；未装备实际能力时，不存在可独立生效的所属辅助。
- 辅助只修饰所属能力，不默认影响心法、其他能力或所有分支。
- 连接图表示归属和供能关系，不表示辅助按图上排列依次执行。
- 同一心法下的所有实际能力共享同一个灵力池，不为每条分支复制容量和恢复收益。

## 心法是资源池，不是攻击调度器

心法至少声明：容量上限、恢复间隔、单次灵力恢复量、对应角色魔法值消耗、实际能力槽数量。

到达恢复时机时，按统一恢复规则扣除角色魔法值并补充池中灵力。不得在没有支付对应资源的情况下凭空恢复，也不能超过容量上限。

心法不分配轮流攻击机会、不统一控制所有能力的攻击间隔，也不限制“整个池子每次只执行一个能力”。恢复间隔与各能力间隔是独立计时。

## 武器和技能独立计时、按次取能

每个实际能力拥有自己的基础间隔和单次灵力消耗，并独立维护当前计时状态。

```text
实际能力到达自己的执行时机
    ↓
检查执行条件，并向所属心法池申请本次所需灵力
    ↓ 灵力足够且满足条件
扣除本次灵力 → 执行武器攻击或技能效果
```

- 灵力不足时不能正常执行本次能力，不允许负灵力或隐式改扣角色魔法值。
- 多个能力可以同一时刻执行，前提是共享池中的资源足够支付各次消耗。
- 同刻取能由负责该实体的客户端统一处理，扣除结果必须一致，不能让多个分支重复使用同一份资源。
- 缺能不等于能力未装备；计时未到、等待供能、已触发是不同状态。
- 实际触发与命中是不同事件。投射物已经生成不等于正式命中，不能用播放动画代替客户端战斗算法的实际命中判定。

## 攻击速度与施法速度的作用

攻击速度影响武器的攻击间隔，施法速度影响法术的攻击间隔（即施法间隔），两者按作用对象分别计算：

```text
武器实际攻击间隔 = 武器基础攻击间隔 / 攻击速度倍率
法术实际攻击间隔 = 法术基础攻击间隔 / 施法速度倍率
```

不能用攻击速度替代施法速度计算法术间隔，也不能用施法速度替代攻击速度计算武器间隔。角色初始点数对两项倍率的收益沿用角色规范，不因此新增可分配属性。

两种速度均不默认改变心法恢复间隔、恢复量、容量或角色魔法值恢复。不得因同时计算动作速度和攻击间隔而重复获得两次完整的频率增益。

独立冷却、持续伤害频率、投射物速度、引导过程与施法前后摇不自动套用额外速度收益；有这些机制时按统一技能规范补充明确行为。施法速度不能仅被解释为缩短读条而不影响法术攻击间隔。

## 正式连接、供能与计时策略

以下为统一执行策略：

- 能力到达执行时机后缺能时等待，不空过本次机会、不借用角色魔法值；满足条件并成功执行后重新计算该能力的间隔。
- 同一模拟时刻先处理心法恢复，再按武器、技能顺序检查取能与执行；允许资源足够的多个能力在同刻执行，不是心法轮流分配攻击机会。
- 心法池已满时不扣除角色魔法值。
- 恢复量超过剩余容量时，只恢复可容纳的部分，按实际转换灵力量占基础单次恢复量的比例扣除魔法值。
- 角色魔法值不足以支付该次实际转换成本时，跳过本次恢复，不产生免费灵力。
- 这些策略由公共模拟统一实现，内容配置和共创机制不得各自替换。具体容量、成本和间隔仍属于内容数值，不因策略正式化而全部固定。

## 辅助修改效果与成本

辅助可以在允许范围内改变所属能力的效果、消耗或间隔，例如多重投射、过载和节能。最终消耗、间隔和效果由统一算法组合计算，不能仅修改说明文字。

装备或卸下辅助后，所属能力的资源需求应同步变化。

辅助兼容性、叠加算法及二次触发边界由公共规则控制。不得通过共创脚本绕过池子供能、获得无限辅助格或形成无限触发链。

## 资源竞争与构筑取舍

```text
理论平均供给 = 单次恢复灵力 / 恢复间隔（秒）
某能力满速需求 = 最终单次灵力消耗 / 最终执行间隔（秒）
总满速需求 = 所有已装备能力满速需求之和
```

这些是供需预览，不是保证触发频率：还受角色魔法值、恢复离散时机、池容量、单次消耗及执行条件影响。

- 池容量提供瞬间储备，不能提高持续供给。
- 攻速和施法速度分别提高对应能力的取能频率，不能自动提高心法供给。
- 一条分支消耗资源后，其他分支可用资源随之减少。
- 总需求超过供给时，不能维持全部能力满速执行。
- 平均供给足够也可能发生瞬间竞争；能力单次消耗超过容量时，不能仅靠等待触发。
- 心法恢复还受到角色魔法值的长期供给限制。

玩家界面必须清楚表达这些关系，不用单一“伤害提升”掩盖消耗或频率代价。

## 装配与体验界面

装配界面提供心法、武器、技能及所属辅助的装备和卸下，展示槽位归属、最终消耗与间隔，并提示共享供需关系。辅助与所属能力一同管理，不能在能力移除后继续产生独立效果。

确认装配后返回测试位置，由已装配能力自动运行。测试位置展示池中资源、能力计时、触发次数及等待供能原因；不提供手动攻击、补能或直接修改参数的操作。更换构筑返回装配界面。

这是当前构筑测试的交互约定，不代表正式游戏禁止移动、选目标等操作，也不自动允许正式战斗中随时更换装备。

## 原型参数与待确定边界

网页已用于确认核心体验，但以下内容不因原型实现而成为不可变的正式规则：

- 示例心法、武器、技能与辅助的名称和具体数值。
- 原型中的一部心法、两个能力槽、每个能力一个辅助格；正式装备数量与格数范围另定。
- 原型的 300 魔法值、初始池满、攻速 1 倍、固定命中与零防御木桩。
- 角色魔法值的正式恢复方式，以及入场、换心法、轮间成长时资源和计时如何继承。
- 无合法目标、执行中断、消耗预扣与退还的具体策略。
- 多辅助叠加顺序、重复辅助限制、触发型辅助规则及是否允许多个心法。

连接、供能和计时采用本文件的正式策略；本节待定项不撤销已经确认的策略，也不授权创作者自行决定未明确的其他政策。
