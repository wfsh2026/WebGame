# 角色与怪物：基础显示和控制规范

## 范围与规则归属

本文件定义实体表现、玩家操作和怪物行为基线。首版已实现基础控制及近战怪物，具体范围和数值见 [当前实现](../implementation/forest-survival.md)；未列入的扩展行为不能视为已有实现。

角色属性仍以 [角色规则](../../content/rules/characters.md) 为准；自动攻击、心法供能及能力计时仍以 [核心战斗规则](core-combat.md) 为准。本文件不改变秘境流程、死亡后的流程、奖励和复活规则。

## 圆形图像实体

角色与怪物统一采用“圆形外框＋固定形象贴图”：图像填充圆内区域，超出部分裁切，圆外透明。适用于玩家、队友、普通怪、精英和 Boss，开发及正式内容均遵守；变更此表现结构须由用户明确要求。

移动和冲刺作用于整个实体；攻击通过独立近战技能特效、投射物、地面预警和远程技能特效表达。画像保持固定，不制作行走、挥手、抬臂、伏身、收爪、拉弓、张嘴等姿态或骨骼动画。

- 圆心对应实体的世界坐标；图片、圆形边框、方向提示和状态表现跟随该坐标。
- 图像按比例缩放并裁切，不拉伸变形；构图保证主体在圆内清晰可见，必要时配置裁切中心。
- 本地角色、队友和敌人以边框样式、标记及名称区分，不能只依赖颜色。精英等身份标记放在圆外，不遮挡主体。
- 圆内图像保持直立；朝向使用圆外的小箭头或短弧表达，不旋转整张头像。
- 生命条放在圆形上方；动作提示、护盾弧、残影和受击闪光属于表现层，不改变逻辑尺寸。
- 图像缺失时使用符合 [资源规则](../../content/rules/assets.md)的备用美术图像并保留身份标识，不使用简单几何图形占位；实体仍按正常逻辑运行。

### 角色与怪物的表现边界与信息分工

- 实体反馈允许整体移动、停顿、缩放、震动、发光、闪白和淡出。
- 独立技能特效可以播放序列帧、旋转、伸缩和位移；这些变化不能作用于圆内画像的姿态。设计说明中的“攻击动作”“技能动画”必须明确指实体整体变化还是独立特效，不使用含糊描述暗示肢体动作。

| 表现层 | 承担的信息 |
| --- | --- |
| 圆内静态画像 | 角色或怪物身份、形象及可识别的行为类型 |
| 圆形外框 | 玩家身份或怪物普通、精英、Boss 等级，战斗中保持可识别 |
| 实体整体变化 | 蓄势、受击等即时反馈 |
| 圆框外方向标记 | 朝向、防御方向 |
| 地面预警 | 危险位置、范围和生效时间 |
| 独立技能特效 | 实际攻击过程 |
| 声音 | 辅助提示关键时机 |

等级边框不得兼作攻击倒计时或冷却圈，也不得被受击、蓄力等效果覆盖到无法识别等级。画像构图与边框制作遵守 [资源规则](../../content/rules/assets.md)。

### 攻击预警与判定一致

设计角色或怪物技能时，分别说明实体整体如何变化、特效在哪里发生、预警和判定如何对应。以下仅说明表现方式，不新增招式或数值：

| 行为 | 实体与画像 | 独立攻击表现 |
| --- | --- | --- |
| 剑斩 | 圆形实体按移动规则运行，画像不挥手 | 实体附近播放刀光或剑影 |
| 扑击 | 圆形实体停顿后整体冲出，画像不伏身或收爪 | 地面路线预警、残影和命中爪痕 |
| 重槌 | 画像不抬臂，可整体发光或震动 | 落点预警、槌影和地面冲击 |
| 射箭 | 画像不拉弓 | 从配置的发射位置生成箭矢，沿攻击方向飞行 |

碰撞与伤害由战斗算法计算，不从画像里的手、武器或特效像素推导。

- 每个攻击明确准备、锁定、生效和结束阶段，说明何时允许追踪、何时停止调整；锁定后不得无提示改变方向或落点。
- 预警的位置、范围与时间必须对应实际攻击；连击、二次爆炸和延迟攻击的每段新增危险均须提供对应预警。
- 瞄准线只提示方向，不代表已经命中；投射物到达并满足命中条件时才结算伤害。
- 攻击结束后及时移除危险提示；装饰残留不得暗示不存在的持续伤害，实际持续伤害则必须保留清晰提示。
- 预警和特效制作遵守 [资源规则](../../content/rules/assets.md#美术表现要求)。
- 危险预警位于地面，实体图像在其上方，生命条和关键状态保持可读。

### 怪物技能预警表现

适用于普通怪、精英和 Boss 的全部技能预警，所有怪物共用下列视觉规则。

- 危险区域使用浅红色半透明填充，外沿使用清晰的红色细边框。填充保持通透，边界清楚可辨。
- 预警作为独立的地面危险区域绘制，形状按技能实际攻击范围确定。圆形攻击显示圆形区域，扇形攻击显示扇形区域，冲锋显示对应长度、宽度和方向的通道区域。
- 预警的位置、大小和朝向对应实际攻击判定，边框表示危险区域的外沿。
- 所有怪物共用同一套填充与边框样式，技能差异通过预警的位置、形状、范围和方向表达。

### 显示与判定分离

实体整体缩放、震动等仅用于视觉反馈，不自动改变逻辑位置、碰撞半径或攻击范围；基础显示尺寸与反馈动画的临时变化分别处理。

基础实体采用圆形逻辑包围区域，声明以米为单位的碰撞半径。基础显示圆与逻辑圆在世界空间保持同心、同半径，边框、阴影及特效不计入半径。

素材像素尺寸、裁切比例和镜头缩放不能改变碰撞半径。攻击范围、索敌范围及格挡覆盖范围单独定义，不从图片或特效反推。圆形半径与米到显示像素的比例不由各内容包自行决定。

地图障碍和边界阻挡移动；冲刺也不能穿过障碍。实体接触规则不能由不同怪物自行选择。接触本身不默认造成伤害。

## 玩家操作

| 输入 | 基础行为 |
| --- | --- |
| W / S | 向上 / 下移动 |
| A / D | 向左 / 右移动 |
| 同时按相邻方向键 | 斜向移动 |
| 按下 Shift | 发起一次定向冲刺 |
| 按住空格 | 持续格挡；松开后结束 |

鼠标不承担基础移动或攻击输入。现有演示的点击寻路、方向键移动只是原型行为，不作为这套基础控制的必需功能。基础攻击继续按已装配能力自动运行，不新增手动攻击键。

### 移动与朝向

- 相反方向同时按下时相互抵消；斜向输入归一化，斜向速度与单方向一致。
- 移动速度沿用角色属性计算，未分配属性时为 3 米/秒，不从演示中的像素速度推导正式数值。
- 最近一次有效移动方向作为角色朝向，停止移动时保留；首次出现默认朝向画面下方。
- 自动攻击的目标选择与移动朝向分离，不能因为头像面朝某方向就默认限制所有能力的索敌方向。
- 不增加惯性加速或松键滑行；受控制效果时，实际移动以对应控制规则为准。

### Shift：定向冲刺

冲刺定义为一次短时间、有限距离的快速位移，不是按住持续加速。

- 按下瞬间有有效移动输入时沿输入方向冲刺；无有效输入时沿保留朝向冲刺。
- 冲刺开始后锁定方向，本次冲刺途中不转向；结束后恢复当前 WASD 输入控制。
- 按下沿只触发一次；长按和键盘重复事件不连续冲刺。冷却期间的请求不缓存为之后的自动冲刺。
- 遇障碍或边界时在合法位置结束，不穿墙、不跨越未允许的地形。
- 冲刺不自带无敌、伤害、击退或接触伤害豁免；只有另外明确的能力才能提供这些效果。
- 冲刺用短残影和方向轨迹表达，HUD 展示是否可用及剩余冷却；残影不参与判定。

不得擅自从角色灵力池扣费，也不因定义冲刺就新增体力属性或耐力系统。

### 空格：持续格挡

基础格挡采用正面防御：按住空格进入格挡，防护方向取进入时的角色朝向；松开后退出。

- 格挡期间停止主动移动并锁定防护方向；松开后按当前 WASD 输入恢复移动。
- 格挡期间不发起新的自动技能施放，各能力原有计时与心法恢复不因格挡重置。退出后仍按各能力规则检查执行条件，不补发格挡期间的攻击次数。
- 已生成的投射物和持续效果按原规则继续；客户端动画不能直接取消读条、引导或前后摇。
- 只有处于防护扇区内且标记为可格挡的命中进入格挡结算；后方命中、不可格挡攻击和未声明可格挡的持续伤害按原规则处理。
- 防护方向、判定扇区和命中来源由负责该实体的客户端战斗逻辑处理。投射物按接触时的来向判断，近战按攻击源方向判断；范围攻击必须明确格挡判向来源，不能默认取特效中心。
- 格挡表示防御能力，不默认完全免伤、反弹、完美格挡、格挡条或破防系统。
- 使用朝向一致的护盾弧表示格挡，成功格挡给出独立反馈；受击闪光不表示获得无敌时间。

不能用画面护盾代替实际减伤。

### 动作冲突与输入释放

| 当前状态 | 新输入 | 处理 |
| --- | --- | --- |
| 普通状态 | 同时请求格挡与冲刺 | 优先格挡，不发动冲刺 |
| 格挡中 | Shift 或 WASD | 不冲刺、不主动移动；松开空格后恢复当前移动输入 |
| 冲刺中 | WASD | 保留输入，冲刺结束后生效 |
| 冲刺中 | 按住空格 | 不中断本次冲刺；结束时仍按住则进入格挡 |
| 冲刺中 | 再次按 Shift | 忽略，不排队 |
| 已死亡或禁止操作 | 任意战斗输入 | 不发起移动、冲刺或格挡 |

格挡暂停发起新能力；冲刺本身不增加自动攻击频率，也不重置能力计时。

游戏区域获得焦点且没有文本输入或阻挡操作的界面时，才接收战斗输入。空格不触发页面滚动。输入框、聊天及菜单不应误触角色操作。

窗口失焦、打开阻挡操作的界面或离开场景时清空本地按键并提交停止移动、解除格挡意图；已经生效的冲刺按服务器规则结束。恢复焦点不沿用旧的按住状态，也不补发冲刺。服务器对输入失联设置超时保护，避免角色持续移动或永久格挡；后台或失焦不暂停正式对局。

## 怪物基础控制

下述怪物行为由具有明确运行归属的客户端推进和判定，服务器协调必要状态与事件，见 [客户端连续表现与同步](client-presentation.md)。

怪物由客户端战斗行为逻辑控制，与角色共用坐标、圆形包围区域和移动碰撞基础，不接收玩家键盘输入。怪物不默认拥有玩家的冲刺和格挡；具有这些能力时应引用已实现的专门行为，并提供前置提示。

### 基础行为链

基础近战怪物采用：待机 → 获取目标 → 接近 → 攻击前摇 → 攻击判定 → 后摇 → 重新决策。受控和死亡可按统一规则打断行为。

- 索敌选择范围内最近的有效敌对玩家；距离相同时按稳定实体标识排序。已有目标仍有效且未脱离追击范围时保持目标，避免不断来回切换。
- 接近目标时避开障碍；到达攻击距离后停下并进入前摇。圆形实体间的距离按中心距离扣除双方半径计算，不能把贴图边缘作为攻击距离。
- 基础近战进入前摇时锁定本次攻击方向，给予玩家走位、冲刺或面向格挡的机会；不在命中瞬间无提示转向。
- 判定时按实际位置和攻击区域决定命中，前摇开始时目标在范围内不保证之后命中。一次攻击对同一目标最多结算一次，不能按渲染帧反复扣血。
- 后摇结束后重新检查目标、距离和攻击条件；失去目标时停止本次追击并重新索敌，不穿墙直达目标。
- 目标死亡、不可被选中或离开追击范围时清除目标。追击范围、索敌范围及无法到达目标时的重试间隔、脱离策略均由公共行为参数约束，不无限累积寻路请求。
- 死亡后立即停止主动移动、索敌和新攻击，退出可攻击目标集合；死亡淡出只负责表现，已生成效果按所属技能的生命周期规则处理。

远程、冲锋、巡逻、召唤等是后续行为扩展，不把尚未实现的机制写成可直接使用的配置。怪物数量、退出条件与掉落引用继续遵守 [怪物规范](../../content/rules/enemies.md)。

### 基础表现反馈

| 状态 | 角色 | 怪物 |
| --- | --- | --- |
| 待机 / 移动 | 圆内图像跟随位置，方向标记同步 | 同角色，方向由当前行为决定 |
| 攻击准备 | 按能力定义提示 | 前摇显示攻击方向或范围；不可格挡攻击另加形状或符号提示 |
| 攻击发生 | 展示实际能力效果 | 展示实际攻击区域或投射物，不以整张头像接触代替命中 |
| 受击 | 短闪光与生命变化 | 同角色；不默认产生硬直或击退 |
| 受控 | 状态图标或明显标记 | 同角色，不能仅停止动画而继续攻击 |
| 死亡 | 显示死亡状态 | 圆形图像淡出，表现结束清理对象 |

关闭装饰特效时仍保留攻击预警、格挡方向及不可格挡提示。

## 内容制作边界

角色内容沿用初始 20 点及既有属性规则，不得独立覆盖基础操作。怪物不自动套用玩家的初始点数预算。

后续配置需要表达以下语义，精确字段名由内容格式模块统一定义，本文件不创建临时 JSON 协议：

- 公共表现：图片资源引用、圆内裁切中心、身份标记；统一逻辑圆规则下的半径。
- 角色控制：引用公共移动、冲刺与格挡规则，不在每个角色中复制一套参数和算法。
- 怪物行为：已实现的行为类型、移动速度、索敌与追击距离、攻击距离、前后摇、间隔、攻击区域和技能引用。
- 命中效果：伤害类型、是否可格挡及必要的判向来源；不从动画名称猜测战斗行为。

首版已采用角色半径 0.4 米、实体可重叠以及具体冲刺、格挡和怪物参数，见 [当前实现](../implementation/forest-survival.md)。不能把首版数值扩大为共创内容可任意覆盖的规则。
