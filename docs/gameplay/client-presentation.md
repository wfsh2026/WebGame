# 客户端战斗运行与关键同步

## 已确认的职责方向

2026-11-13 用户明确要求客户端负责战斗运行和操作体验，服务器负责联机协调、必要转发、掉落同步及永久数据保存，最大限度减少服务器职责，只在关键处同步，优先保证流畅体验。本规则替代此前“客户端仅预测表现、服务器裁定全部战斗”的要求，不改变战斗公式、秘境流程和资产政策。

## 职责划分

| 客户端 | 服务器 |
| --- | --- |
| 即时处理输入、移动、冲刺、格挡与反馈 | 身份、连接、入场和房间生命周期协调 |
| 运行供能、能力计时、攻击、投射物、碰撞、命中、伤害、生命和死亡 | 接收必要战斗事件和结果，去重、排序与转发，不默认重新模拟完整战斗 |
| 运行怪物行为，平滑表现远端实体 | 协调共享实体运行归属、阶段和关键检查点，支持加入与重连 |
| 运行局内构筑与成长，提交关键变化及成果 | 同步掉落身份、归属、拾取与消耗结果，防止重复领取 |
| 合并同步状态，不等待回包才产生操作反馈 | 汇总成果，由大厅业务按规则保存永久数据、结算及资产流水 |

客户端战斗结果可以作为联机事件和成果提交来源。服务器保留身份、场次、阶段、格式、事件归属和防重复等必要检查，不默认逐次复算伤害、供能或碰撞。客户端不能直接写永久数据库，也不能提交任意金币或永久物品要求直接入账。

## 关键同步原则

- 本地战斗连续运行，网络发送频率与渲染频率分离；移动、攻击和命中不等待服务器逐次许可。
- 优先同步加入离开、阶段变化、必要位置与朝向、关键攻击或结果、死亡复活、构筑变化、掉落拾取及结算成果；可由事件和参数重建的投射物、粒子及装饰不逐帧广播。
- 移动采用必要采样与远端插值，共享状态按变化发送；加入、重连或需要纠偏时提供必要检查点，不默认持续广播完整世界。具体频率按需要确定，不固化旧实现频率。
- 共享怪物、共享生命和同一攻击必须有明确运行归属及唯一结果来源，不能由多个客户端分别结算后累加。归属选择、移交和冲突合并在具体任务中明确，不默认指定房主，也不回退为服务器运行全部战斗。
- 使用场次、实体、事件标识和序号处理重复、乱序及迟到；攻击、死亡、掉落和拾取不能因转发或重连重复生效。
- 断线、失焦及浏览器后台节流不能造成共享战斗永久停顿；归属移交、检查点恢复和全部客户端离线策略在实施时明确，不假定已有自动恢复能力。
- 隐藏掉落配置与永久奖励规则继续保留在服务器；掉落生成按对应规则处理，不能因战斗迁移而公开隐藏数据。
- 新增服务器计算或高频消息前说明必要性与最小同步内容，不为严格防作弊恢复整套服务端战斗模拟。

## 算法与表现

- 客户端复用公共纯 TypeScript 战斗算法，保持供能、命中和属性公式一致；公共算法不依赖 Phaser、DOM、网络或数据库。
- 普通同步不持续将本地角色拉回旧坐标；纠偏区分本地操作、共享状态冲突和重连恢复。
- HUD 和文字按变化刷新，不逐帧更新整页 React；降低画质只减少装饰，不减少战斗判定或必要同步。
- 失焦清空输入并发送停止意图，共享会话仍按运行归属方案继续协调。

## 现有实现与迁移边界

本次仅修改规范，不代表代码已迁移。此前的 `presentationOnly`、服务器战斗步进和固定快照属于旧实现，不能作为继续扩展服务器战斗职责的依据。

迁移时沿实际调用链同步调整客户端、房间、协议和结算；不能只删除服务器逻辑而遗漏客户端运行、共享状态归属及掉落一致性。既有历史实现说明保留为代码定位依据。完成后交由用户体验，不自动执行编译检查或玩法测试。
