# 构筑成长与有等级物品

本文件维护大厅构筑、局内成长和有等级物品的通用边界，适用于开发区与正式内容。连接、供能与计时仍遵守 [核心战斗规则](core-combat.md)，永久资产及奖励遵守 [经济规范](../../apps/api-server/rules/economy.md)和[结算规范](../../apps/api-server/rules/settlement.md)。规则确认不代表对应代码已完成。

## 已确认的成长结构

- 大厅配置初始构筑，秘境内通过成长完善构筑。入场时根据大厅构筑建立本次秘境状态；局内升级、槽位变化和装配变化只修改本次状态，不先修改永久物品再在退出时尝试还原。
- 离开秘境后清除局内临时成长，不回写大厅构筑；这不免除已有物资、装备及死亡经验惩罚，也不阻止按规则独立发放最终奖励。
- 心法升级可以增加连接武器或技能的能力槽，并改善容量、供能等效果。新增能力仍共享所属心法的灵力池，增加槽位不代表供能自动充足。
- 武器和技能升级可以强化能力效果、增加辅助槽；辅助宝石自身可以升级，增强或改变对所属能力的修饰效果，不默认扩散到其他分支。
- “初始一个槽”属于示例，不是统一初始值。各内容在公共规则允许范围内定义初始槽数、等级上限、解锁节点及升级效果，不无限扩展。
- 怪物掉落和最终结算奖励可以包含具有等级的技能石、装备、心法；获得物品不自动代表允许带出或免除失败损失。

## AI 设计与实现约束

- 区分角色局内等级、物品自身等级和物品局内临时提升的语义，不用一个含义不明的等级字段混合表示。
- 每份成长方案说明升级收益、资源代价、槽位变化、兼容性与上限；展示最终消耗及供需变化，不能只展示伤害收益。
- 升级、掉落和波次奖励应有可感知的来源差异，允许内容重叠；作用于同一能力的相同效果复用统一计算与叠加规则，不为每种奖励另写公式。
- 设计换装时必须说明临时强化归属、换下后的保留方式、槽位减少及不兼容装配的处理，不通过换装复制强化或让失效辅助继续生效。
- 新物品不能未经玩家选择直接覆盖已有构筑；具体储备和换装交互确定后再实现。
- 局内成长由客户端运行，关键变化由房间协调同步，永久物品与发奖由大厅业务管理；掉落与结算都保留明确来源，不能由技能或客户端直接修改永久资产。

## 尚待确认的细节

以下是设计方向或候选方案，不能作为已经批准的默认实现：

- 物品自身等级与临时提升的计算关系、封顶方式；“3 级物品临时升到 5 级，允许带出时仍为 3 级”是候选模型。
- 临时强化是否绑定具体物品实例、换下是否保留；槽位溢出内容是否退回局内储备，以及储备容量和领取方式。
- 战斗中换装的权限、时机及其资源和计时继承规则。
- 角色升级是否主要提升当前装备、掉落是否主要提供新物品、波次是否主要补足构筑缺口；各奖池、比例、关键波次间隔和保底机会。
- 装备是否具有独立经验条，以及具体等级上限、槽位解锁节点、升级数值和辅助叠加政策。
- 失败后是否允许新生成的最终结算物品进入大厅仓库。不能通过将冒险所得改名为结算奖励绕过 [失败惩罚](failure-penalties.md)。
