# 通用代码与协作规范

适用于所有代码任务。具体领域规则按根 AGENTS.md 路由读取。

## 用户约定

- 开发完成后不需要执行编译检查。
- 功能开发完成后须按下述要求编写功能效果测试页面并对照参考图；除此之外，未经用户要求，不设计或执行其他测试、验收流程。
- 调用的参数表达式内不直接嵌套方法或函数调用，先创建局部变量保存结果，再传入调用。
- 调用参数能在一屏内清楚显示时保持同一行，不采用每填写一个参数就换行的格式。
- 自定义方法或函数的参数不超过三个；参数较多时使用有明确类型的参数对象，避免单纯为规避限制而过度封装。
- 少使用 `ref`、`out`；减少 `static` 类，保持代码简洁，避免过度设计。
- 不主动编写或修改文档；用户明确要求规范或文档变更时除外。
- 同一张未修改且仍保留在上下文中的图片不重复查看；优先查看缩略图，需要时仅查看细节区域。

## 文档维护

- 写入文档的内容须为已确认规则或可核实事实，明确适用范围；不收录待确认清单、未采纳方案、猜测或用“待定”占位的条款。
- 缺少产品决定时在对话中列出问题，用户明确后再写入，不自行补成规则，也不另建待确认文档。
- 已确认但尚未实现的规则可以保留，并与当前实现事实区分；不得将未实现误写为未确认。
- 已确认的建议、示例和可配置范围须明确其用途，不能伪装成强制数值或实现事实。

## 修改边界

- 开始任务时确定目标、允许修改的目录、公共接口和禁止修改的部分。
- 内容任务默认仅修改指定的 `content/packs/<pack-id>/`。
- 新机制需要代码时，先确定扩展接口，再修改明确授权的代码模块。
- 不自行增加依赖、升级框架、修改根配置或替换已有公共系统。
- 不夹带无关重构、批量格式化、其他内容包的修改。
- 不提交密钥、真实账号数据、生产连接字符串或未经授权的素材。
- 不为可配置内容生成任意脚本执行器，不使用 `eval` 或动态执行配置字符串。
- 不使用类型断言或 `any` 绕过模块边界、网络校验和资产权限。

## 交付

构建授权、测试网页和正式发布统一遵守 [发布流程](../deploy/release-workflow.md#固定发布顺序)。

简明说明改动、使用方式、待用户测试的功能及已知限制。如未运行检查，应如实说明，不声称验证通过。

### 功能效果测试页面

- 功能开发完成后，编写或完善测试页面，重点展示实际运行的功能效果；复用实际功能实现，不用静态示意或模拟效果替代。
- 有参考图时，通过测试页面对照实际效果与参考图，检查两者的差距；发现不一致或其他问题时，继续开发修改，再次对照，直至实际效果与参考图一致后交用户体验。
- 实际功能效果的运行、截图与参考图对比须在后台进行，不抢占用户当前窗口焦点或键鼠输入，不影响用户操作；需要可见窗口或桌面交互时，可在其他桌面执行，不切换用户正在使用的桌面。
- 测试页面的入口、构建和部署遵守 [发布流程](../deploy/release-workflow.md)，功能效果展示整合到统一测试入口。
