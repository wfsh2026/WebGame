# 历史验证及测量边界

以下为 2026-11-05 的历史记录，不是当前任务的验证结果，也不要求继续开发时自动重跑。代码与参数可能随后改变。

2026-11-05 用户明确要求过后台测试，已有下列脚本；默认不自动重跑。浏览器和协议脚本会在测试服务器创建账号、房间及结算数据，不是纯读取。

| 文件 | 覆盖 |
| --- | --- |
| `tools/online-simulation-smoke.ts` | 两轮纯模拟、格挡方向、缺能、独立攻击、辅助范围、冲刺边界 |
| `tools/online-browser-smoke.mjs` | 双后台浏览器、组队、两轮、成长、重连、最终结算与返回大厅 |
| `tools/online-protocol-smoke.mjs` | 越界方向、旧序号、输入超时、失败结算，不是严格位置防作弊证明 |
| `tools/online-prediction-smoke.ts` | 无回包首帧移动、攻击和实体连续推进、去重、预测不扣正式生命值 |
| `tools/online-feel-smoke.mjs` | 双后台浏览器、单程额外 200 ms 消息延迟、响应时间和连续性 |

纯模拟使用 `corepack pnpm exec tsx tools/<文件名>`；浏览器脚本使用 `node tools/<文件名>`。脚本默认连接内部测试服务器，部分写死 Windows Chrome 路径，更换环境前先读脚本，不能直接在 Linux 执行。

完整两轮浏览器测试曾通过，最终结算连续重试 3 次未重复发奖。流畅性修复后，额外约 400 ms 往返消息延迟的短时测试中，诊断坐标下一帧响应（采样约 1～6 ms）、测试机约 144 FPS、帧间隔 P95 约 7 ms、运行异常 0。

这些是特定测试机、短时低怪物量场景，不是所有设备的承诺，也未证明 48 怪物、多房间或弱设备的峰值性能。响应测的是测试按键调用至诊断坐标更新，不是物理按键到显示器的端到端延迟。`.cache/online-test` 和 `.cache/online-feel` 是本机可丢失产物；无异常、流程跑通与手感流畅必须分别判断。

运行方法见 [本地运行](../local-running.md)，服务器操作见 [部署操作](../../deploy/operations.md)。
