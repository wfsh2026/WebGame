# 当前实现限制与待补齐差异

已确认心法、武器、技能和辅助采用分类独立文件及 ID 引用，见 [内容包规则](../../content/rules/packs.md#独立内容与清单职责)。当前首包仍为清单内嵌配置，独立 Schema、引用解析与加载迁移尚未实施；本次仅更新文档。

基于 2026-11-05 首版实现及后续规则确认整理。下文区分已实现行为与待完成工作，不自动授权迁移、实现、测试或发布。按当前任务阅读涉及的条目。

- 已确认开发验证区与发布流程，见 [开发区规则](../../development/RULES.md)和[发布流程](../../deploy/release-workflow.md)。本次仅增加规则入口，未迁移旧演示、建立统一开发导航、配置独立开发环境或实际发布；当前网站继续视为内部测试环境。

- 用户已确认 [死亡与失败惩罚](../gameplay/failure-penalties.md)：个人死亡扣升级经验，全队失败丢失秘境所得物品及带入物资，身上装备按幸运修正概率掉落。物资、装备掉落及经验扣除尚未实现；当前失败奖励不代表正式惩罚已落实。本次仅更新规则文档。

- 秘境大厅目前是 React 等待/成长面板，不是可走动的 Phaser 场景；`hall.json` 存在但没有完整大厅场景加载器。
- 用户已确认最终结算后弹出本局个人收益界面，各玩家主动关闭后分别返回游戏大厅，不要求统一返回或倒计时。当前实现是页面内结果展示及“返回游戏大厅”按钮，弹出结算界面与关闭交互仍需按 [核心主循环](../gameplay/core-loop.md#最终结算界面与返回)补齐；本次仅更新规则，未修改 UI。
- 首个秘境的内容格式、角色、奖励、地图入口存在硬编码；仅修改清单不代表所有服务和 HUD 会自动适配。通用内容加载/导出、配置化奖励与审核工具未完成。
- `content-sdk` 只有规则，没有扩展运行时；不能配置一个未实现的行为名就宣称支持。
- 没有 PvP、商店、经营、永久强化、装备掉落、战斗中装配或多角色正式业务，旧演示不代表已接通。
- 没有触屏控制方案与目标设备性能标准，自适应页面不等于支持手机战斗。
- 没有并发压测、自动滚动发布、房间模拟持久化、崩溃补偿或完整备份恢复流程。
- 当前单轮数据库记录是“场次 + 轮次”的聚合个人成果数组，不是独立的每人每轮明细表；扩展明细追踪前按结算规范补齐，不能声称该表已有每玩家独立唯一约束。
- 用户已确认各玩家独立结算并保存个人结果，当前聚合轮次记录需按 [结算规范](../../apps/api-server/rules/settlement.md)补齐；本次仅更新文档，未调整数据库。
- 用户已确认武器攻击间隔使用攻击速度、法术攻击间隔使用施法速度；当前模拟仍复用一个由初始点数计算的倍率，两项初始收益相同，但尚未分别建模其运行修饰，不能据此宣称支持独立的两项速度增益。
- 房间启动调用 `/internal/recover`，目前会将所有 `active` 场次标为 `interrupted`；未经改造不能并行启动第二个正式房间进程，也不能盲目重启真实对局。
- 本地位置只做类型、地图合法性等检查，不做严格速度防作弊。这是用户选择，不是必须恢复等待服务器确认的遗漏。

现场部署及发布/回退边界见 [部署操作与现有环境](../../deploy/operations.md)。
