# 开发验证区规范

## 职责和结构

未发布功能先在本目录开发，通过统一开发入口供用户体验：

```text
development/
├─ web/                       # 开发入口及功能导航
└─ features/
   └─ <feature-id>/
      ├─ client/              # 功能客户端实现
      ├─ server/              # 按需添加的服务端扩展
      └─ content/             # 候选配置和资源
```

子目录按需创建，不为每个功能预建全部结构；当前尚未实现上述入口和功能加载机制。

候选内容使用 [内容包规则](../content/rules/packs.md)约定的相同包内目录及 ID 引用方式，不在开发区另建一套心法、武器、技能或辅助格式。

## 开发约束

- 复用已有账号、房间、战斗、资产和公共接口，不搭建第二套同用途系统。
- 客户端、服务端和内容均遵守对应领域规则，开发区不能绕过固定主循环、属性、供能和结算规则。
- 正式应用、公共包和正式内容不得反向依赖本目录。开发入口可通过公开接口引用正式能力。
- 必须修改公共核心时，在指定开发分支中处理，范围限于任务所需；代码进入公共目录不代表已经发布。核心规则的变更仍须用户明确要求。
- 不直接修改其他开发功能，不将多个候选功能混为无法独立确认的实现。

## 体验与环境

构建授权、唯一测试网页、更新记录、环境隔离和发布选择统一遵守 [发布流程](../deploy/release-workflow.md)；交付与检查要求遵守 [通用开发规范](../docs/development.md)。目录存在不代表开发导航、独立服务或访问限制已完成。

## 功能转正

用户确认可纳入正式功能后，按 [发布流程](../deploy/release-workflow.md)将实现整理到对应正式模块。迁入后移除重复实现；保留的开发体验入口引用同一份实现，不长期维护开发版、正式版两套相同逻辑。

旧演示按独立任务逐步归入本区。迁移前仍使用交接文档记录的真实路径，不假定旧代码已经移动。过时演示不得作为正式业务数据或规则的来源。
