# 永久资产与经济规范

## 资产归属

构筑隔离、物品等级和临时成长遵守 [构筑成长规范](../../../docs/gameplay/build-growth.md)。

| 数据 | 权威管理方 |
| --- | --- |
| 局内等级、技能、临时物品和增益 | 客户端运行；服务器协调关键变化与掉落归属 |
| 击杀、目标完成、个人积分和名次 | 客户端产生战斗成果；房间去重汇总并协调共享结果 |
| 永久角色成长、经营、背包、货币 | 大厅业务服务 |
| 最终奖励与资产流水 | 大厅业务服务 |

局内物品不会自然变成永久资产。可带出的物品需要明确转换规则。

死亡经验扣除、全队失败后的物品与物资损失、幸运修正的装备掉落统一遵守 [死亡与失败惩罚](../../../docs/gameplay/failure-penalties.md)。应区分本次秘境物品、带入物资、身上装备和仓库资产，不以失败为由清空其他资产。

## 积分与产出

- 积分获取规则由各秘境自行设计，平台不统一限制得分行为、积分来源或其分值，不要求各秘境使用同一套获取公式。积分由对应秘境规则计算，客户端提交成果、服务器进行必要汇总与一致性处理，并归属具体玩家。
- 积分设计自由不等于可绕过永久资产发放；奖励换算、失败损失和幂等结算仍遵守对应公共规则。本次确认不新增统一兑换比例。

- 不同秘境的原始积分不能直接套用相同货币兑换比例。
- 奖励依据经审核的秘境、难度、有效参与和成果模板计算。
- 内容作者不能自行设置无限产币、直接写余额或跳过奖励上限。
- 所有资产变化具有明确来源和可追溯流水，客户端展示余额不作为可信依据。

- 货币、背包、商店、永久角色成长使用同一资产业务入口，禁止各自绕过资产规则写库。
- 扣除、占用、归还和购买应有防重处理；并发请求不能造成余额或物品超支。
- 不擅自实现生产、离线收益或交易。
- 结算发奖同时读取 settlement.md。

涉及角色初始属性或永久成长时读取 [角色规则](../../../content/rules/characters.md)。初始 20 点配置不能与后期成长混用。
