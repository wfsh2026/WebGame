# 部署规范

构建授权、测试与正式发布、环境隔离、版本保留及清理统一遵守 [发布流程](release-workflow.md)。

网页静态资源与服务器独立发布，正式环境采用 HTTPS/WSS。初期采用模块化服务，不按每个业务领域拆分微服务。

当前用户授权的例外是 8080 HTTP/WS 内部测试，保护旧首页和 `/mhxy/`，不自行开放 80/443。现场结构及发布前置条件见 [部署操作](operations.md)。

房间内保存实时对局状态，不逐帧写数据库。房间进程向大厅服务提交可信结算，大厅服务执行永久资产事务。房间扩容、跨进程发现和 Redis 在确有需要时设计。

失焦、断线和恢复遵守 [客户端同步规范](../docs/gameplay/client-presentation.md)。

- 当前测试环境已使用 Linux、Docker、Nginx，Nginx 直接分发静态资源；CDN 尚未配置，不能将规划当作已部署能力。
- 只提交示例配置和占位值，真实凭据放服务器环境，不写入镜像、网页资源或日志。
- Linux 路径区分大小写，资源路径命名必须一致。
- 内容与协议版本成套发布，不兼容时拒绝开新房间，既有房间保留锁定版本。
- 修改部署不等于获准发布到生产环境，发布目标及权限按用户任务确定。
