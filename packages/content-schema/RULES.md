# 内容格式与校验规范

定义心法、技能与辅助格式前读取 [核心战斗规则](../../docs/gameplay/core-combat.md)，按 [内容分类入口](../../content/AGENTS.md)追加读取对应类型；区分基础属性与角色唯一灵力池；心法不再配置魔法转换成本，不照搬原型数据结构。

- 使用 JSON 配置和 Zod 运行时校验，类型声明不能替代输入处理。
- 统一定义内容清单、角色、地图对象、技能、怪物和事件格式；内容作者不能自行发明字段语义。
- 属性明确单位、有效范围、必需项和缺省行为，未识别的运行字段不得偷偷改变规则。
- 校验 ID、引用、资源路径和兼容版本；拒绝越界路径、脚本字符串和任意远程资源地址。
- 源配置只有一份；客户端与服务器产物由同一份配置导出，隐藏数据只输出到服务器侧。
- 内容版本与格式版本分别管理，变更时明确兼容性及旧内容处理方式。
- 心法、技能和辅助的独立文件、ID 及清单引用遵守 [内容包规则](../../content/rules/packs.md#独立内容与清单职责)。迁移时同步实现相应 Schema、ID 解析、引用完整性与兼容处理，不能只拆分 JSON 文件而不更新消费端。
- 可引用 contracts、simulation 的公开类型，不依赖 content-sdk 或应用，避免循环。
- 先读 ../../content/rules/packs.md，再读任务对应的角色、地图、技能、怪物或事件规范，不读取无关类型。

角色格式必须遵守 [角色规则](../../content/rules/characters.md)，只允许配置初始点数，不提供核心基础值或换算系数的覆盖字段。
- 当前 `src/index.ts` 已实现首包清单、角色点数和受限 Tiled 对象地图的校验；房间启动会读取并解析。通用各类型 Schema、独立校验 CLI 和导出工具尚未完成，不能把规则清单当作所有能力已实现。
