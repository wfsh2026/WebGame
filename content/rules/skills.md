# 技能内容规范

适用于 AI 新增、扩展技能及技能构筑设计；先从角色与怪物的圆形实体战斗推导玩法，再确定效果、辅助与成长。本文约束设计与内容制作，不因列出某种机制就表示运行时已支持。

行为与表现设计先读 [实体显示与控制](../../docs/gameplay/entity-controls.md)；等级与槽位成长读 [构筑成长规范](../../docs/gameplay/build-growth.md)。

适用范围：内容包 `skills/` 下的全部近战与远程技能配置。统一 `kind: skill`，通过 `skillType: melee | ranged` 区分类别；`delivery` 单独描述近战、投射或范围效果。原武器归为近战技能，原技能（含战旗、陷阵与剑阵）归为远程技能。

目标采用独立技能文件与 `skill` 类型 ID，通过 ID 引用；结构与迁移边界见 [内容包规则](packs.md#独立内容与清单职责)。

先读 [核心战斗规则](../../docs/gameplay/core-combat.md)。技能是连接心法的实际能力，分为近战、远程两类，独立执行计时，到时从共享灵力池取能，不通过心法统一轮询触发。声明基础执行间隔、单次灵力消耗和辅助格数量；两类技能的伤害属性和速度作用统一遵守核心战斗规则。辅助配置另读 [辅助规则](supports.md)。

- 优先组合已实现的投射物、范围伤害、增益、触发条件和效果。
- 明确冷却、消耗、距离、持续时间、目标筛选和叠加规则，属性必须有单位和有效范围。
- 投射物、召唤物和持续效果必须有数量限制、持续时间或其他退出条件。
- 持续效果和订阅在失效、阶段退出或房间销毁时释放。
- 技能只能影响局内状态，不能直接改永久属性、背包或货币。
- 客户端运行技能施放、命中和伤害，服务器仅协调必要事件与结果，遵守 [客户端战斗与同步规则](../../docs/gameplay/client-presentation.md)。
- 不复制已有技能代码实现配置差异，不通过未定义字段改变规则。
- 新效果机制另读 ../../packages/content-sdk/RULES.md 和 ../../packages/simulation/RULES.md；新增配置格式另读 ../../packages/content-schema/RULES.md。

## 从圆形实体的实际战斗开始设计

角色与怪物都是圆形外框内的固定画像。技能设计先回答：攻击从哪个世界坐标发出，以什么路径或区域接触敌方逻辑圆，玩家如何通过移动改变结果。具体显示、碰撞、预警和操作沿用 [实体显示与控制](../../docs/gameplay/entity-controls.md)，不在技能内另造基础操作。

- 直线、扇形、圆形、环形、链路和地面区域是逻辑几何描述；说明起点、朝向、长度、宽度、半径、内外沿及目标圆的参与方式。宽度写明是全宽还是半宽，范围写明按圆心距离、边缘距离还是区域与逻辑圆相交计算。
- 区分索敌、施放、飞行、触发与伤害范围，不共用一个含义不明的“射程”。分别说明障碍对移动、投射物、范围伤害和连锁的影响，引用已有算法；新增穿墙行为需明确提出，不能由视觉表现隐式获得。
- 明确发射点是施法者、固定阵地还是其他已实现的来源；范围跟随实体或固定在世界坐标，必须写清。技能特效独立于画像，不能依赖画像挥手、转身或武器骨骼挂点。
- 说明玩家通过靠近、拉开、绕侧、把敌人引到一条线或区域、留在或离开阵地中的哪些操作获得收益，以及失去站位条件后的损失。不能仅写“走位输出”“打击感强”。
- 说明面对近身追击、远程压制、冲锋、正面防护、持续危险区域等实际怪物行为时的长处和弱点；优先引用目标秘境已实现的怪物，不为证明技能价值虚构现有敌人能力。
- 对普通、精英和 Boss 分别说明目标数量、体型、控制抗性和输出窗口的影响。不得假定大体型可以按渲染帧反复受伤，也不默认控制对所有层级等效。

## 《流放之路2》的参考范围

用户已明确技能参考《流放之路2》。采用其技能与辅助组合、行为改造、条件联动和构筑取舍的设计方向；本项目的连接、供能、自动攻击及基础控制仍以各自领域规则为准。参考不授权修改核心规则，也不授权使用其商业美术、音频或直接复制技能数据。

可核实的参考依据：

- [官方技能系统介绍](https://pathofexile2.com/en/early-access)：技能宝石提供能力，辅助宝石可以显著改变所属技能行为；官方介绍的辅助数量不作为本项目槽位上限。
- [官方 0.3.0 更新说明](https://www.pathofexile.com/forum/view-thread/3826682)：辅助系统调整强调能力组合，移除了每个角色只能使用一份同类型辅助的限制，并引入更多辅助层级。这是特定版本的历史事实，不能引用旧攻略把“全角色同类辅助唯一”写成本项目规则。
- 同一更新中的 Forge Hammer、Frost Darts、Snap 等说明展示了地面对象、目标状态与后续攻击相互作用的设计。这里借鉴的是“建立条件，再利用条件”的关系，具体技能行为与数值仍须按参考版本核实。

AI 引用具体机制时提供来源和版本，区分原作事实、项目已有机制与本次建议。不混用一代、二代及不同补丁的数据；不把 Spirit、魔力保留、武器切换、手动连招或原作异常体系直接等同于项目心法灵力池及已有状态。

### 技能与构筑的职责

- 新技能先说明相对已有技能增加了什么战斗选择，例如命中路径、空间布局、状态利用或供能节奏；只有名称、颜色、元素或伤害倍率变化时，说明为何需要独立技能，而不是已有技能的配置变体。
- 基础效果、技能自身成长和辅助修饰分别描述，避免把完整构筑全部塞进基础技能，或让辅助成为独立攻击分支。辅助规则只维护在 [辅助规范](supports.md)。
- 组合写成具体事件关系：哪个能力建立何种状态或场地，哪个能力在什么条件下利用它，条件是否消耗，失败或过期后如何继续。说明没有配套能力时的作用和局限，不把建议组合写成唯一装配。
- 自动攻击由各能力独立计时。需要先挂状态再引爆的组合，必须说明自动索敌、施放条件和资源竞争如何让两者衔接；不能要求玩家按不存在的攻击键，也不能把连接图排列当成连招执行顺序。
- 分清移动朝向、格挡朝向和技能瞄准方向。需要攻击某个特定敌人时，说明现有索敌如何选中它、走位怎样改变候选目标；当前逻辑做不到的优先级或筛选标为需要新增机制。
- 每个方案同时说明清群、单体、移动中输出和防御时的表现，允许有明显专长；不要求每个技能都兼备清群、追踪、控制、爆发和续航。

## 时间、命中和资源说明

下列是设计必须说明的语义，不要求为每项新增字段；没有相应机制的项目明确说明不适用。

| 项目 | AI 必须说明 |
| --- | --- |
| 自动施放 | 何时检查目标与条件，无目标或条件不成立时如何等待，是否保留既有目标 |
| 准备与锁定 | 起手、方向或落点锁定、生效、收招，以及期间是否能移动、追踪、冲刺、格挡或被打断 |
| 计时 | 基础间隔、最终间隔、独立冷却、持续时间、伤害跳频各自的意义及速度属性影响 |
| 资源 | 首次施放、持续跳、重复发射、重新布置分别何时付费，辅助后的最终成本、缺能与中断处理 |
| 命中 | 直接命中、爆炸、持续伤害、返程、分裂与连锁分别如何判定，同次攻击对同目标的次数上限 |
| 状态 | 来源与归属、持续时间、刷新或叠加、强弱覆盖、消耗条件、传播次数及目标死亡后的处理 |
| 生命周期 | 投射物、阵地、标记与派生效果的数量和寿命；宿主卸下、施法者死亡、阶段退出时的处理 |

资源计算引用 [核心战斗规则](../../docs/gameplay/core-combat.md#资源竞争与构筑取舍)，同时展示单次支出、最大单次需求、满速持续需求及对其他分支的竞争。持续或引导能力按实际付费节奏列出总需求，不能用启动成本代表整个持续过程；不得默认免费续射、缺能改扣角色魔法值或返还未约定的资源。

多重、穿透、分裂、连锁、返程、余震和传播的组合须分别声明哪些事件能够触发哪些后续效果、是否继承辅助、是否再次收费、能否命中原目标及链路终止条件。沿用现有去重与事件来源规则，不能因新增特效或事件转发重复伤害，也不能让派生效果无限再次派生。

## 成长与多人体验

- 按 [构筑成长规范](../../docs/gameplay/build-growth.md)说明基础可用效果、关键等级变化、辅助槽解锁、成本变化与上限。行为变化应能从路径、覆盖、状态或节奏中辨认，不能把描述中的成长当成已实现效果。
- 设计每个成长节点时说明它强化了哪种原有玩法、是否改变索敌或兼容辅助。节点数量与等级沿用目标内容，不把当前首包节点固定为所有技能的统一模板。
- 多人状态明确是个人归属还是共享，队友能否利用、消耗或刷新；同类战旗、地面区域、控制和持续伤害重叠时引用统一叠加规则。没有规则的新增交互在对话中提出，不能自行变成默认共享收益。
- 输出、控制与防御反馈应让玩家理解技能何时施放、命中、缺能、中断或失效。友方技能不能遮盖敌方危险预警、圆形身份外框与格挡方向；装饰降级后保留必要战斗信息。
- 声明同时存在的投射物、阵地、状态及派生次数边界，考虑多玩家、多辅助和密集怪物同时触发。具体性能预算沿用 [资源规范](assets.md)，不自行发明已达成的性能指标。
- 联机归属、唯一结果来源、同步去重及客户端运行职责遵守 [客户端战斗与关键同步](../../docs/gameplay/client-presentation.md)，不为一个新技能增加整套服务端复算。

## AI 提交技能方案的内容

按以下顺序提交，简短技能可以合并描述，但不得省略影响玩法的条件；这是设计说明结构，不是测试或验收流程。

1. **战斗画面与定位**：圆形角色、敌人处于什么相对位置，玩家怎样移动，技能解决什么问题，有什么弱点。
2. **与现有内容的区别**：复用或扩展哪些能力，新增独立技能的理由；引用原作时附具体来源与版本。
3. **完整效果过程**：自动选目标、起手、锁定、付费、生效、命中、状态与退出，使用米、秒、次数等明确单位。
4. **构筑关系**：适配的心法与能力组合、条件建立和利用、可用及不可用辅助、最终供需及取舍。
5. **成长与怪物体验**：基础与关键等级效果，对目标秘境具体怪物及不同层级的应对变化。
6. **实现范围**：已有配置能完成什么、需扩展哪些机制、涉及哪些代码与资源入口；未确认的新产品决定留在对话中。
