# Web 美术素材制作规范

适用于 AI 生成、人工制作、既有素材修改及导出，覆盖开发区、测试网页和正式发布。采用高清原稿留存、按显示尺寸导出、分层复用、按场景加载的方式，同时考虑清晰度、下载体积、纹理内存和绘制开销。

制作前读取 [资源规则](assets.md)。实体表现遵守 [实体显示与控制](../../docs/gameplay/entity-controls.md)。本文件定义制作要求，不表示相关工具、图集或加载策略已经实现。

## 绘制前的素材说明

每份素材开始制作前，明确以下信息；复用同一规格的批次可以共用说明，并列出各素材差异。

| 项目 | 必须说明的内容 |
| --- | --- |
| 用途 | 画像、边框、图标、投射物、地面特效或场景等 |
| 显示规格 | 预计显示尺寸、镜头最大缩放、实际渲染分辨率及导出尺寸 |
| 构图 | 视角、中心点、主体范围和必须保留的识别特征 |
| 分层 | 独立导出的部分及共用资源 |
| 透明与边缘 | 是否透明、光晕范围和裁切留白 |
| 动画 | 独立特效是否需要序列帧、时长和循环方式；角色与怪物画像不制作姿态动画 |
| 资源归属 | 公共资源或具体秘境、命名和版本 |

## 清晰度与构图

- 优先保证缩小后的主体轮廓、明暗层次和关键特征，减少小尺寸下消失或形成噪点的碎纹理。
- 同类素材统一视角、光照方向、比例和细节密度，不通过增加原图分辨率代替有效构图。
- 画像、等级边框、状态效果与技能特效分别制作；名称、等级数字和伤害数值等动态文字不烘焙进图片。
- 透明背景必须具有真实透明通道，不带棋盘格、白底或明显白边；裁切时保留必要光晕和柔和边缘。
- 高清原稿和可编辑资源用于后续修改；游戏使用整理、裁切和缩放后的导出资源。概念对照图不能直接作为最终图集。

## 怪物画像与等级边框

- 画像直接针对实际圆形显示区域构图，将代表行为的关键特征保留在圆内，保证小尺寸下仍可辨认；不能默认将全身概念图缩小裁切即可使用。
- 同族普通、精英和 Boss 保留共同识别特征，通过画像结构体现层级差异，不只依赖换色或放大。
- 保持一致的圆内显示区域。同等级怪物复用统一边框体系，通过轮廓、粗细、结构和标记共同区分等级，不能只依赖颜色。
- 边框装饰不影响碰撞范围，不遮挡画像关键特征或血条。具体配色、单环或双环、冠形标记等样式由对应美术方案确定，不固定为跨秘境要求。

## 显示尺寸与导出规格

按最大实际显示需求选择纹理尺寸，同时考虑镜头缩放与实际画布渲染分辨率。不得仅根据设备像素比无条件放大全部资源；增加素材尺寸不能弥补画布本身分辨率不足。

以下是选择起点，不是强制统一尺寸或已经确定的性能预算。实际需求超出时按用途调整并说明原因，不将所有素材一律导出为最大规格。

| 素材 | 建议运行时尺寸 | 说明 |
| --- | --- | --- |
| 角色、怪物画像 | 128×128 或 256×256 | 按最大显示尺寸选择，Boss 不默认使用更大贴图 |
| 等级边框 | 128×128 或 256×256 | 与画像匹配，同等级复用 |
| 技能石、心法、装备图标 | 64×64 或 128×128 | 背包用小图，详情页按需加载大图 |
| 投射物、小型命中特效 | 64×64 或 128×128 | 裁掉无用透明区域，保留必要光晕 |
| 范围攻击、爆炸特效 | 256×256 或 512×512 | 按实际覆盖面积选择 |
| 地面与场景 | 分块、可复用贴图 | 不默认用一张超大纹理覆盖整张地图 |

例如最终需要约 128 像素覆盖的画像，通常不必加载 1024 像素版本。原稿可保留更高分辨率，但不随运行资源默认全部下载。

## 文件格式与资源成本

| 用途 | 格式策略 |
| --- | --- |
| 原稿及可编辑资源 | 保留原始文件，透明原稿保存无损 PNG |
| 透明画像、图标、边框 | 比较无损 WebP 与 PNG，选择体积较小且边缘清楚的版本 |
| 不透明背景、场景插画 | 优先考虑有损 WebP，压缩质量按画面需要确定 |
| 特效动画 | 图片图集与帧数据，不默认使用 GIF |
| 复杂游戏美术 | 导出栅格纹理，不依赖运行时反复绘制复杂 SVG |

所选格式必须由项目实际加载链路支持；格式选择不授权自动升级依赖或引入第二套渲染体系。

下载体积与纹理内存分别考虑。普通图片上传为 RGBA8 纹理时，基础占用约为宽×高×4 字节：2048×2048 约 16 MiB，4096×4096 约 64 MiB，未计 mipmap、解码副本和其他开销。PNG 改为 WebP 不代表同尺寸纹理内存同比减少。

GPU 压缩纹理作为后续按需求引入的优化，需要明确设备兼容、加载支持和回退方案；本规范不要求立即接入。

## 图集与加载

- 按同时使用的资源组织图集，例如公共界面、当前秘境怪物、当前秘境特效和场景资源；不把所有秘境塞进一张图。
- 常用图集以 1024×1024 或 2048×2048 为候选规格，容量超出时优先拆页；这是建议起点，不是设备能力结论。
- 图块之间保留间距并做边缘像素扩展，避免缩放采样串入邻图颜色；具体宽度结合过滤与 mipmap 策略确定。
- 裁切透明空白时保留原始尺寸、偏移和中心信息，保证多帧动画及叠加层位置稳定。
- 同一种怪物的多个实例共享纹理，不按实体复制图片或重复生成纹理。
- 场景按需加载相关资源，离开后根据引用关系释放；共用资源仍被使用时不得提前销毁。
- 图集有助于资源组织和批处理，但不能承诺所有对象只产生一次绘制调用。

## 特效与画质分级

- 技能优先复用纹理，结合必要的少量动画帧与变换表现；帧数根据效果需要确定，不预设所有特效必须使用同样数量的帧。
- 控制光晕、烟雾、残影的透明覆盖面积、重复层数与寿命，不为每只普通怪叠加多层全尺寸光效。
- 明确特效的生成上限及回收时机，避免对象与纹理持续累积；具体数量由场景预算确定。
- 降低画质时优先减少装饰粒子、残影和光晕，保留攻击范围、锁定方向、生效时机和等级识别，不改变正式判定。
- 美术细节不得模糊预警边界；范围与时间一致性遵守 [实体规则](../../docs/gameplay/entity-controls.md#攻击预警与判定一致)。
